Una prueba real de publicación, con información inventada

  1. Descarga DEMO_A.wpcx y DEMO_B.wpcx. Guárdalos en una carpeta exclusiva de pruebas.
  2. En HidroLog PC 2.0.4 utiliza Abrir proyecto sobre una copia del paquete. No importes la demo dentro de un proyecto real.
  3. Revisa las corridas ficticias. Para cambiar el resumen puedes ajustar una recuperación o añadir una corrida contigua; guarda el proyecto.
  4. Abre el publicador de PC incluido en el repositorio. Selecciona el .wpcx guardado y pulsa Validar y guardar en cola.
  5. Con «Simular sin internet» activado, el envío queda pendiente. Desactívalo y pulsa Enviar pendientes a GitHub.
  6. Cuando el publicador confirme el envío, abre este dashboard en otra computadora o teléfono y actualiza. El resumen se lee desde GitHub; no depende de que el PC siga encendido.

Requisito del publicador: Python 3.9+ y una sesión de Git con permiso de escritura en este repositorio. No se pide ni publica un token en el navegador. Los visitantes solo leen.

El paquete contiene capturas parciales intencionales; los avisos del software no significan que se haya validado un logueo completo. No se ha probado una tablet ni se ha modificado el instalador.

El envío es real, pero manual. El publicador utiliza la autenticación del PC; la web no puede escribir registros en GitHub. El filtro de clientes no es un permiso ni un inicio de sesión.

Para producción

La cola debe integrarse transaccionalmente en HidroLog. GitHub se sustituiría por una API, base central, usuarios y archivos privados. El servidor comprobaría permisos por cliente y proyecto en cada operación. El trabajo de Android y la reconexión automática necesitan desarrollo y pruebas específicos.

Lo que conservamos

Los instaladores, fórmulas, manuales, paquetes de cliente y dashboard MODFLOW permanecen separados e intactos. Esta demo no importa archivos de producción.
